# WSL2 Runbook

Known-good post-reboot setup for this repository.

## 1. DNS configuration

If DNS resolution breaks after a reboot, apply the fixed resolver config:

```bash
sudo bash scripts/apply_wsl_dns_config.sh
```

This writes:

```ini
[boot]
systemd=true

[user]
default=seok436

[network]
generateResolvConf=false
```

and pins `/etc/resolv.conf` to:

```text
nameserver 1.1.1.1
nameserver 8.8.8.8
```

After changing `/etc/wsl.conf`, run this from Windows:

```powershell
wsl --shutdown
```

Then reopen the distro.

## 2. Shell bootstrap

`/home/seok436/.bashrc` sources `scripts/auto_shell.sh`.

When you enter `/home/seok436/projects/eit-market-data`, it will:

- run `uv sync --extra all --extra dev` when the venv is missing or stale
- activate `.venv`
- load `.env`
- if `/mnt/c/Users/$USER/.cache/eit-market-data/krx-profile/cookies.json` exists,
  export `EIT_KRX_COOKIE_PATH` and `EIT_KRX_PROFILE_DIR` to reuse the Windows KRX session

Do not commit `cookies.json` into the repository. It is a live authenticated session artifact.

## 3. Post-reboot verification

Run the repo preflight:

```bash
python scripts/preflight_kr_data.py --as-of 2026-03-06 --ticker 005930 --skip-news
```

Expected outcome:

- DNS checks for `data.krx.co.kr`, `fchart.stock.naver.com`, `ecos.bok.or.kr` are `OK`
- `public:prices`, `public:market-cap`, `public:benchmark`, `public:sector` are `OK`
- `dart` is `OK`
- `ecos` is `OK` or explicitly `DEGRADED`
- 뉴스 진단은 기본 bundle 경로와 분리되어 있으므로 `--skip-news`가 기본이다

Exit codes:

- `0`: all checks passed
- `1`: at least one hard failure
- `2`: no hard failures, but at least one degraded dependency

## 4. DART API — IP 차단 주의

**`opendart.fss.or.kr`에 단시간 내 반복 요청하면 IP가 당일 차단된다.**

증상: `Connection reset by peer` / `RemoteDisconnected` / `curl: (56)` / HTTP 000

### 접속 안 될 때 절차

1. **접속 상태 단 1회 확인** — 실패하면 즉시 중단하고 재시도하지 않는다:
   ```bash
   curl -s --max-time 10 \
     "https://opendart.fss.or.kr/api/company.json?crtfc_key=${DART_API_KEY}&corp_code=00126380" \
     | python3 -m json.tool | head -5
   ```

2. **오프라인 빌드로 전환** — 기존 스냅샷에서 캐시 시딩 후 ci_safe 빌드:
   ```bash
   python scripts/seed_dart_cache.py
   python scripts/build_kr_snapshot.py --profile ci_safe --as-of $(date +%Y-%m-%d)
   ```

3. **차단 해제 대기** — 자정(00:00 KST) 이후 자동 해제. 강제로 뚫으려 하지 않는다.

### 정상 작동 확인 (차단 해제 후)

```bash
rm -rf data/dart_cache/   # 캐시 제거 — fresh 테스트
python scripts/build_kr_snapshot.py --profile ci_safe --as-of $(date +%Y-%m-%d) --force
# fundamentals > 0, filings > 0 이면 DART 직접 접속 성공
cat artifacts/snapshots/$(date +%Y-%m)/manifest.json | python3 -m json.tool | grep -A12 field_coverage
cat artifacts/kr/snapshots/$(date +%Y-%m)/manifest.json | python3 -m json.tool | grep -A12 field_coverage
```

상세 규칙: `docs/api-keys.md` DART 섹션 및 `.claude/rules/dart-api-limits.md`

## 5. Current caveats

- Default KR runtime은 스냅샷 공식 경로 기준으로 pykrx(price/market/sector/benchmark)를 우선 사용하고,
  보완/점검은 FDR 경로를 활용합니다.
- KRX login scripts remain available only for manual diagnostics and legacy experiments.
- Historical month-end `market_cap` replay uses `data/market/cap_daily/*.parquet`, generated by
  the official `scripts/crawl_kr_data_pykrx.py` collector (legacy fallback: `crawl_kr_data_fallback.py`).
- `scripts/fill_kr_cap_daily_gap.py`은 legacy backfill 보조 도구입니다.
  정식 수집은 `scripts/crawl_kr_data_pykrx.py`를 우선 사용하고,
  필요 시 legacy `scripts/crawl_kr_data_fallback.py`를 병행합니다.
- `scripts/crawl_kr_data.py`는 인증 기반 복구/수동 디버깅용 legacy 경로입니다.
- `scripts/backfill_all.py` caches 32 DART quarters per ticker by default (`--dart-quarters`) for multi-year point-in-time replay.
- `./run_crawling.sh kr` and auto mode run the official pykrx crawler first when historical `cap_daily` coverage is incomplete.
- `START_MONTH`/`END_MONTH`가 지정되지 않으면 `END_MONTH`는 기준월(`BASE_MONTH`, 기본: 직전 달)로, `START_MONTH`는 `LOOKBACK_MONTHS`만큼 자동 계산됩니다(기본 12개월).
- Override `START_MONTH`/`END_MONTH` for bounded replay runs, for example `START_MONTH=2023-05 END_MONTH=2026-03 ./run_crawling.sh auto`.
- `BASE_MONTH`는 기준일을 강제 지정할 때(`BASE_MONTH=2026-03`) 사용하고,
  `LOOKBACK_MONTHS`는 자동 관리 기간(월 수)을 바꿀 때 사용합니다.
- 로그 확인 및 속도 튜닝:
  - `LOG_DIR` (기본 `logs`)에 실행별 `crawling_<RUN_ID>.log`가 기록됩니다.
  - `RUN_ID`를 지정하면 로그 파일명 고정 가능 (예: `RUN_ID=manual_2026_05`).
  - `CRAWL_DELAY_SECONDS`(기본 `0.5`), `DART_DELAY_SECONDS`(기본 `5.0`), `MAIN_PHASE_DELAY_SECONDS`(기본 `1`)로 단계별 딜레이를 조절하세요.
  - `MIN_CAP_DAILY_FILES`/`CAP_DAILY_THRESHOLD`(기본 `100`/`90`)로 phase1/phase3 선행 요건 기준을 조정합니다.
- For replay builds, generate `cap_daily` first, then run `scripts/build_kr_snapshot.py`.
- ECOS monthly and quarterly series must be fetched with verified item codes and full-page pagination; this repository now handles that internally.
- DART `data/dart_cache/` (diskcache) persists `FundamentalData`/`FilingData` objects; seed with `scripts/seed_dart_cache.py` when DART API is inaccessible.
